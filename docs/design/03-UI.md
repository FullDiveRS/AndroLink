# Design: AndroLink.UI (the custom C# UI framework)

A retained-mode UI framework rendered with SkiaSharp. AndroLink.Manager is
built entirely on it; it exists so the product owns its whole rendering story
and to satisfy the "create a UI framework in C#" goal with something real:
layout engine, control set, theming, animation, input routing.

## Core abstractions

### UIElement (`Core/UIElement.cs`)
Every node. Owns layout properties (`Width/Height` as `LayoutLength`
Auto/Pixel/Star, `Margin/Padding`, `CornerRadius`, alignment, `Opacity`,
`Visible`), tree management (`Add/Remove/ClearChildren`), the two-pass layout
engine, input event surface, and the render hook.

Layout contract (WPF-flavored, simplified):

```
MeasureInternal(available):
    coreAvailable = available - Margin            (- Pixel sizes as constraint)
    content       = MeasureOverride(coreAvailable)   [virtual, excludes Padding]
    DesiredSize   = content + Padding (+ MinWidth/MinHeight) + Margin

ArrangeInternal(finalRectWithMargin):
    FinalRect     = finalRectWithMargin - Margin
    contentRect   = FinalRect - Padding
    ArrangeOverride(contentRect)                  [virtual, positions children]
```

Default `MeasureOverride/ArrangeOverride` iterate `VisualChildren` with
alignment; containers (Window, Border, ScrollViewer, TabControl, ListBox...)
override `VisualChildren` to route through their own content property.

### Window & input (`Core/Window.cs`)
`Window` supplies `VisualChildren` = Content + Overlay (overlay hit-tested
first, only when it has children - modal dialogs block the content). Pointer
routing: hit-test the deepest visible element → enter/exit tracking →
press/release with capture → wheel/key/text bubble from the focused element
with `Handled` flags. `UIApplication.Post` marshals backend threads to the UI
thread via the platform dispatch queue.

### Renderer (`Rendering/UiRenderer.cs`)
`RenderTree`: translate → optional alpha layer → background → `OnRender` →
border → rounded clip → children. Primitives: rounded fills/strokes, soft
shadow, lines, `WrapText` (greedy word wrap with hard-break for over-long
words). Text metrics go through `UiFonts` (SKPaint with cached per-(family,
weight) typefaces; Segoe UI on Windows, Noto Sans fallback elsewhere).

### Theming (`Theming/Theme.cs`)
`Theme.Current` - dark/light palettes with roles (Window/Surface/SurfaceAlt/
SurfaceHover/Border/TextPrimary/TextSecondary/Accent trio/Selection/Danger/
Success/Warning/Scrim/ScrollbarThumb). Controls read colors at render time;
constructed `Background`s are snapshot values (documented limitation - page
rebuilds pick up theme switches).

### Animation (`Animation/Animator.cs`)
Central tween list pumped by the platform at ~60 fps: `Animate(from, to,
duration, onTick, easing, completed, owner)`. Easings: Linear, EaseIn/Out,
EaseInOut, EaseOutBack. `owner` auto-invalidates the element each frame.
Used for hover transitions, tab/content fades, modal scrims, progress pulse,
caret blink.

## Layout convention (important)

`FinalRect` is **parent-relative**: the renderer (`UiRenderer.RenderTree`)
translates cumulatively down the tree, and hit-testing / `AbsolutePosition()`
subtract/accumulate the same offsets. Containers therefore arrange children in
their own coordinate space: `ArrangeInternal` hands `ArrangeOverride` a rect
whose origin is the element's *padding* (never its position), panels position
children relative to that origin, and `AlignChild` treats its slot the same
way. Margins are stripped exactly once (inside `ArrangeInternal`), so panels
pass the full desired size and position the outer edge. Cross-axis semantics:
in vertical stacks `HAlign.Stretch` fills the width; in horizontal stacks
`HAlign.Stretch` children keep their natural width, `VAlign.Stretch` fills the
height, and `HExpand` children share leftover width (that is what
`Spacer.Fill()` uses). `MaxWidth`/`MaxHeight` clamp measure and arrange - pages
use `HAlign.Center + MaxWidth` for balanced wide-window columns.

## Platform abstraction (`Platform/IPlatform.cs`)
`IPlatform` (window creation, run loop, Post, file/folder pickers, clipboard,
Explorer reveal, URL open, file-drop subscription) + `IWindowHandle`. The
framework is testable headlessly: layout tests run without any platform.

## Deliberate limitations
- Single-line `TextBox` (multi-line is a roadmap item).
- `ListView` columns are pixel-width (keeps header/rows aligned simply).
- Theme switches re-style dynamic colors instantly; snapshot `Background`s on
  rebuilt pages update on next rebuild.
- No data binding - pages wire updates explicitly (small app, zero magic).
